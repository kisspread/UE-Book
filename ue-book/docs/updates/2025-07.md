# 2025年7月引擎更新月报

收录仅包含 07-22 开始的 10 天内容。

即便如此，基础系统更新依然很重，**Asset Registry 冷收集从 960 秒 → 421 秒**、**新材质翻译器 (MIR) 新增 21 个节点 + Custom HLSL 支持**、**Substrate 光照路径统一**、**UAF (Unreal Animation Framework) 正式启动**等更新齐头并进。

还解决了多个重大 Bug，例如 AMD GPU 上的 Nanite 挂起、推送模型数组同步遗漏 (UE-186111)、Landscape Edit Layer 调整大小时的数据丢失 (UE-305565)。

---

## ✨ 新功能

**Mass Entity Debugger 大幅功能强化**

> 新增了大量断点类型，包括实体的创建/销毁、标签/片段的添加与删除等，并增加了通过查询或 Gameplay Debugger 进行过滤、命中计数、以及 PIE 会话之间的持久化。
> Mass 框架开发的调试效率大幅提升。
>
> _出处: [2025-07-23](https://github.com/pafuhana1213/UnrealEngine-UpdateTrackerReport/discussions/2)_

**Iris 新增 Creation Dependency 功能**

> 现在可以通过 `AddCreationDependencyLink` 定义对象之间的生成依赖关系。
> 子实体的生成可以延迟到父实体在客户端上存在为止，从而能够严格控制复杂父子关系的同步和生成顺序。
>
> _出处: [2025-07-25](https://github.com/pafuhana1213/UnrealEngine-UpdateTrackerReport/discussions/4)_

**Take Recorder 新增无卡顿时间码记录**

> 通过线性回归推算时间码，即使引擎侧发生帧延迟（卡顿）也不会跳过时间码。
> 录制的稳定性大幅提升。
>
> _出处: [2025-07-29](https://github.com/pafuhana1213/UnrealEngine-UpdateTrackerReport/discussions/9)_

**输入系统新增“确定/返回”用虚拟 FKey**

> 新增加了可绑定的 `Gamepad_Virtual_Accept` / `Gamepad_Virtual_Back` 键，可在不同平台间获得一致操作。
> UI 导航实现得到简化。
>
> _出处: [2025-07-30](https://github.com/pafuhana1213/UnrealEngine-UpdateTrackerReport/discussions/10)_

**蓝图新增异步资产加载节点“Async Load Assets”**

> 新节点可批量异步加载软对象引用列表，并在完成时调用委托。
> 可以轻松实现多资产的高效后台加载。
>
> _出处: [2025-07-30](https://github.com/pafuhana1213/UnrealEngine-UpdateTrackerReport/discussions/10)_

**MegaLights 也可为前向渲染的半透明对象提供近似光照**

> 现在可以使用 Translucency Light Volumes (TLV) 将 MegaLights 的光照近似应用于半透明表面。
> 半透明材质的光照质量得到提升。
>
> _出处: [2025-07-30](https://github.com/pafuhana1213/UnrealEngine-UpdateTrackerReport/discussions/10)_

**Single Layer Water 在移动端 Deferred 渲染中完全支持**

> 在支持 SM5 的移动端 Deferred Renderer 中，Single Layer Water 已完整实现。
> 现在可以在移动端实现包括彩色透射和折射在内的高质量水体表现。
>
> _出处: [2025-07-31](https://github.com/pafuhana1213/UnrealEngine-UpdateTrackerReport/discussions/11)_

**基于 ITF（Interactive Tools Framework）的视口交互**

> 这是一个模块化框架，可以组合环绕、平移、缩放等特定交互来自定义视口行为。
> 附带了复现标准关卡编辑器控制的默认交互集。使用 CVar `ViewportInteractions.EnableITFInteractions 1` 启用。
>
> _出处: [2025-07-31](https://github.com/pafuhana1213/UnrealEngine-UpdateTrackerReport/discussions/11)_

**Unreal Insights 新增堆栈采样分析器**

> Unreal Insights 中新增了用于 CPU 堆栈采样分析的新分析器。
> 瓶颈定位的精度更上一层楼。
>
> _出处: [2025-07-28](https://github.com/pafuhana1213/UnrealEngine-UpdateTrackerReport/discussions/8)_

## 🚀 重大变更

**新材质翻译器 (MIR) 新增 21 个节点 + 支持 Custom HLSL + 支持各种纹理类型**

> MIR 实现了 21 个新节点，包括 Distance Field、Sky Atmosphere 相关节点和各种数学运算等，另外还支持通过 Custom Expression 节点使用用户自定义 HLSL 函数，以及 Volume / 2D Array / Cube Array 纹理类型。
> 与旧翻译器的功能一致性大幅接近。
>
> _出处: [2025-07-22](https://github.com/pafuhana1213/UnrealEngine-UpdateTrackerReport/discussions/1) / [2025-07-31](https://github.com/pafuhana1213/UnrealEngine-UpdateTrackerReport/discussions/11)_

**统一 Substrate 的光照路径**

> 即使使用旧版 GBuffer 格式，也会改用 Substrate 的光照代码路径，从而减少是否启用 Substrate 带来的光照行为差异。
> 同时解决了 AO 重复应用等问题，渲染一致性得到提升。
>
> _出处: [2025-07-24](https://github.com/pafuhana1213/UnrealEngine-UpdateTrackerReport/discussions/3) / [2025-07-28](https://github.com/pafuhana1213/UnrealEngine-UpdateTrackerReport/discussions/8)_

**UMG 与 Enhanced Input 协作，重构输入生命周期**

> 现在改为在构建 UMG Widget 时将输入组件压入输入栈，并在销毁时弹出的方式。
> 这样 Widget 在视口上处于激活状态时才会处理输入，行为更直观，`UUserWidget::InitializeInputComponent` 已被弃用。
>
> _出处: [2025-07-25](https://github.com/pafuhana1213/UnrealEngine-UpdateTrackerReport/discussions/4)_

**开始迁移至 UAF (Unreal Animation Framework)**

> `SkeletonTemplateFramework` 插件的内容已移动到新的核心插件 `UAF` 中。
> Trait 堆栈可在细节面板中直接编辑，还增加了图表编译时的验证，面向 AnimNext 的框架重构已经正式展开。
>
> _出处: [2025-07-25](https://github.com/pafuhana1213/UnrealEngine-UpdateTrackerReport/discussions/4) / [2025-07-28](https://github.com/pafuhana1213/UnrealEngine-UpdateTrackerReport/discussions/8) / [2025-07-31](https://github.com/pafuhana1213/UnrealEngine-UpdateTrackerReport/discussions/11)_

**Mover / ChaosMover 新增传送、Instant Move、Based Movement**

> Mover 和 ChaosMover（异步物理）中新增了传送、可延迟执行的 Instant Move 效果、以及以其他对象为基准的 Based Movement 支持。
> 可以灵活构建支持网络的高级角色移动逻辑。
>
> _出处: [2025-07-28](https://github.com/pafuhana1213/UnrealEngine-UpdateTrackerReport/discussions/8)_

**移除 Mobile FSR 插件**

> 曾为移动端提供 FSR 1.0 的 `MobileFSR` 插件已从引擎中完全移除。
> 今后推荐使用 TSR（Temporal Super Resolution）。
>
> _出处: [2025-07-24](https://github.com/pafuhana1213/UnrealEngine-UpdateTrackerReport/discussions/3)_

**Interchange 导入 FBX 成为默认方式**

> 在编辑器中的 FBX 场景（关卡）导入已经默认通过 Interchange 框架进行。
> 在 UEFN 中，资产导入也已默认化，导入流程的统一持续推进。
>
> _出处: [2025-07-29](https://github.com/pafuhana1213/UnrealEngine-UpdateTrackerReport/discussions/9)_

**Interchange 的 OBJ/FBX 翻译器改为生成材质实例**

> 现在不再生成完整着色器图表，而是生成材质实例，从而实现了导入加速和更便捷的材质管理。
>
> _出处: [2025-07-24](https://github.com/pafuhana1213/UnrealEngine-UpdateTrackerReport/discussions/3)_

**简化 World Partition HLOD 系统的用户体验**

> HLOD Layer 和 Runtime Partition 的属性得到梳理与简化，减少了不必要的嵌套。
> 还新增了专用于独立 HLOD 放置的 Actor `AWorldPartitionHLODOnlyLevelInstance`，使 HLOD 的预览和管理更加轻松。
>
> _出处: [2025-07-24](https://github.com/pafuhana1213/UnrealEngine-UpdateTrackerReport/discussions/3) / [2025-07-25](https://github.com/pafuhana1213/UnrealEngine-UpdateTrackerReport/discussions/4) / [2025-07-29](https://github.com/pafuhana1213/UnrealEngine-UpdateTrackerReport/discussions/9)_

**Media Profile Editor 2.0 成为默认版本**

> 新的 Media Profile Editor 已设为默认，同时带来了 UI/UX 改进以及修复了更改媒体输出类型时的捕获问题等多个 Bug。
>
> _出处: [2025-07-29](https://github.com/pafuhana1213/UnrealEngine-UpdateTrackerReport/discussions/9)_

## ⚡ 性能优化

**Asset Registry 的收集性能得到显著改善**

> 通过异步任务化和引入非缓冲存档，冷收集从 960 秒缩短至 421 秒，热收集从 225 秒缩短至 136 秒。
> 此外，`AssetRegistryState` 的初始化和整理已通过 `ParallelFor` 并行化，并可通过 `EEnumerateAssetsFlags::Parallel` 标志并行枚举资产。大型项目的编辑器启动和 Cook 时间大幅缩短。
>
> _出处: [2025-07-22](https://github.com/pafuhana1213/UnrealEngine-UpdateTrackerReport/discussions/1) / [2025-07-23](https://github.com/pafuhana1213/UnrealEngine-UpdateTrackerReport/discussions/2) / [2025-07-29](https://github.com/pafuhana1213/UnrealEngine-UpdateTrackerReport/discussions/9)_

**Cooker 的资产排序从 5.3 秒缩短至 0.6 秒**

> CookByTheBook 的 `AssetRegistryState` 排序采用了 `ParallelMergeSort`，并减少了 FName 字符串查找开销。
> 40 万个包的排序从 5.3 秒缩短到 0.6 秒。
>
> _出处: [2025-07-22](https://github.com/pafuhana1213/UnrealEngine-UpdateTrackerReport/discussions/1)_

**Interchange 场景导入从 10 分钟缩短至数十秒**

> 包含大量带 LOD 网格的场景中，`ExecuteSceneNodePreImport` 已从 N^2 复杂度优化为线性复杂度。
> 包含 10,000 个网格的场景导入准备时间从 10 分钟以上缩短至数十秒。
>
> _出处: [2025-07-22](https://github.com/pafuhana1213/UnrealEngine-UpdateTrackerReport/discussions/1)_

**为 `.uplugin` / `.uproject` 加载引入 RapidJson**

> 通过从标准 Json 解析器切换为 RapidJson，显著改善了尤其是包含大量插件的大型项目的编辑器启动时间和项目加载速度。
>
> _出处: [2025-07-23](https://github.com/pafuhana1213/UnrealEngine-UpdateTrackerReport/discussions/2)_

**Apple 平台的光标信息异步缓存**

> Windows 环境中光标信息的缓存处理被卸载到任务图。
> 游戏线程的负载得到减轻，UI 被大量使用的场景下性能得到提升。
>
> _出处: [2025-07-23](https://github.com/pafuhana1213/UnrealEngine-UpdateTrackerReport/discussions/2)_

**为 AutoRTFM 引入轻量级共享 Mutex**

> 引入了 `FTransactionallySafeSharedMutex`，在启用 AutoRTFM 时作为 `FTransactionallySafeRWLock` 的后端。
> 减少了内部锁处理的开销。
>
> _出处: [2025-07-24](https://github.com/pafuhana1213/UnrealEngine-UpdateTrackerReport/discussions/3) / [2025-07-25](https://github.com/pafuhana1213/UnrealEngine-UpdateTrackerReport/discussions/4)_

**利用 HarfBuzz 字体缓存加速文本塑形**

> 现在改为使用 HarfBuzz 的缓存系统，无需为每个文本序列重新生成字体信息。
> 特别是阿拉伯语等复杂脚本的文本塑形速度大幅提升。
>
> _出处: [2025-07-30](https://github.com/pafuhana1213/UnrealEngine-UpdateTrackerReport/discussions/10)_

**优化 Windows 鼠标输入处理（每帧最多降低 0.5ms）**

> 优化了鼠标捕获和高精度模式的处理，移除冗余 API 调用，在某些场景下每帧最多可节省 0.5ms 的 CPU 时间。
>
> _出处: [2025-07-30](https://github.com/pafuhana1213/UnrealEngine-UpdateTrackerReport/discussions/10)_

**FullBody IK (PBIK) 求解器优化**

> 通过简化关节约束求解处理、从未解析骨骼更新中排除、提高 Pull Chain Alpha 精度等方式，FBIK 的运行时性能得到提升。
>
> _出处: [2025-07-25](https://github.com/pafuhana1213/UnrealEngine-UpdateTrackerReport/discussions/4)_

## 🐛 Bug 修复

**推送模型的数组属性未能正确标记为脏的问题（UE-186111）**

> 修复了一个严重 Bug：即使修改了其他 Actor 拥有的数组属性，也不会被标记为脏，导致变更可能无法被复制。
> 使用推送模型的多人游戏中，数组复制的可靠性大幅提升。
>
> _出处: [2025-07-23](https://github.com/pafuhana1213/UnrealEngine-UpdateTrackerReport/discussions/2)_

**启用 Landscape Edit Layer 时使用调整大小工具导致数据丢失（UE-305565）**

> 修复了在启用 Edit Layer 的 Landscape 上使用调整大小工具导致数据丢失的严重缺陷。
> 原因是图层复制时 GUID 分配不当，同时修复了清空目标图层时的崩溃。
>
> _出处: [2025-07-23](https://github.com/pafuhana1213/UnrealEngine-UpdateTrackerReport/discussions/2)_

**AMD GPU 上 Nanite 挂起**

> 修复了 Nanite 着色分箱处理中导致特定 AMD GPU 挂起的着色器问题。
> 提升了 AMD 硬件上的开发稳定性。
>
> _出处: [2025-07-22](https://github.com/pafuhana1213/UnrealEngine-UpdateTrackerReport/discussions/1)_

**蓝图重新编译时多播委托绑定累积**

> 修复了一个长期存在的问题：每次重新编译蓝图时，都会重复添加对其他 Actor 的多播委托（事件分发器）的绑定。
> 事件被意外多次执行的问题得到解决。
>
> _出处: [2025-07-26](https://github.com/pafuhana1213/UnrealEngine-UpdateTrackerReport/discussions/6)_

**Iris 中新建子对象的脏状态被屏蔽**

> 修复了在对象 PreUpdate 期间创建的新子对象的脏状态被意外屏蔽，导致无法复制的问题。
>
> _出处: [2025-07-22](https://github.com/pafuhana1213/UnrealEngine-UpdateTrackerReport/discussions/1)_

**NetPhysics 中服务器输入被丢弃（UE-298241）**

> 修复了当服务器端输入缓冲区为空时，可能会丢弃从客户端接收到的输入的问题。
> 网络对战时物理模拟的可靠性提升。
>
> _出处: [2025-07-23](https://github.com/pafuhana1213/UnrealEngine-UpdateTrackerReport/discussions/2)_

**`TIntrusiveMutex` 的致命死锁**

> 修复了核心库 `TIntrusiveMutex` 中可能发生的死锁。
> 提升了多线程环境下的引擎稳定性。
>
> _出处: [2025-07-25](https://github.com/pafuhana1213/UnrealEngine-UpdateTrackerReport/discussions/4)_

**向 ZenServer 进行阻塞下载时发生死锁**

> 通过添加超时，解决了在包 Cook 过程中 `PerformBlockingDownload` 无限等待并导致任务线程死锁的问题。
>
> _出处: [2025-07-23](https://github.com/pafuhana1213/UnrealEngine-UpdateTrackerReport/discussions/2)_

**垃圾回收：固定住的 UObject 不应阻碍所在集群的 GC**

> 修复了通过 `FGCObject` 固定的 UObject 不再阻碍所属集群整体的 GC。
> GC 的行为变得更容易预测。
>
> _出处: [2025-07-23](https://github.com/pafuhana1213/UnrealEngine-UpdateTrackerReport/discussions/2)_

**Cook-on-the-Fly 中材质着色器映射为空的严重缺陷**

> 解决了在 COTF 会话期间发现的材质着色器映射为空的问题。
> 可以避免 COTF 工作流中的渲染问题。
>
> _出处: [2025-07-31](https://github.com/pafuhana1213/UnrealEngine-UpdateTrackerReport/discussions/11)_

**On-Demand Loading 中从不支持部分请求的 CDN 加载时数据损坏**

> 修复了从不支持部分内容请求的 CDN 加载时，IAX (On-Demand HttpClient) 返回无效数据的问题。
>
> _出处: [2025-07-25](https://github.com/pafuhana1213/UnrealEngine-UpdateTrackerReport/discussions/4)_

**大量 Substrate 相关修复**

> 解决了各向异性材质的不正确渲染路径、Clear Coat 的直接光/间接光光照错误、法线相关问题、调试显示缺陷等多个问题。

**头发渲染：MegaLights / 棋盘格渲染时的伪影**

**Oodle / BC6 纹理压缩可能导致崩溃**

## 🔧 API 变更

**将 `UPlayerInput` 的按键获取函数改为 `virtual`**

> `GetKeysForAction` 和 `GetKeysForAxis` 已被设为 virtual，可在派生类中重写。
> 更容易实现自定义输入映射逻辑。
>
> _出处: [2025-07-23](https://github.com/pafuhana1213/UnrealEngine-UpdateTrackerReport/discussions/2)_

**将 `bHiddenEdTemporary` 标志移至 `USceneComponent`**

> 从 `UPrimitiveComponent` 移动到父类 `USceneComponent`，现在所有场景组件都可以使用。
>
> _出处: [2025-07-23](https://github.com/pafuhana1213/UnrealEngine-UpdateTrackerReport/discussions/2)_

**Chaos Physics 碰撞过滤器 API 重构**

> 使用旧 `FCollisionFilterData` 的方法已被弃用，并新增了使用新类型的方法。
> API 的类型安全性得到提升。
>
> _出处: [2025-07-26](https://github.com/pafuhana1213/UnrealEngine-UpdateTrackerReport/discussions/6)_

**强化核心容器和算法的 `constexpr` 支持**

> `TArrayView`、`Invoke`、`TStaticArray` 等核心函数已支持 `constexpr`。
> 借助 C++20 功能，编译期计算的范围得以扩大。
>
> _出处: [2025-07-24](https://github.com/pafuhana1213/UnrealEngine-UpdateTrackerReport/discussions/3)_

## ⚠️ 废弃预告

**`UUserWidget::InitializeInputComponent` 已弃用**

> 随着 UMG 与 Enhanced Input 生命周期的改进，输入组件的初始化和注册已自动管理，该函数变得不再需要。
>
> _出处: [2025-07-25](https://github.com/pafuhana1213/UnrealEngine-UpdateTrackerReport/discussions/4)_

**可弃用传统 Action / Axis 映射的新系统**

> 现在可以在项目设置中将传统映射标记为 deprecated，并在引用它们的蓝图或 C++ 代码中发出警告。
> 有助于逐步迁移到 Enhanced Input。
>
> _出处: [2025-07-31](https://github.com/pafuhana1213/UnrealEngine-UpdateTrackerReport/discussions/11)_

**移除旧的 XR 运动控制器函数**

> 在 5.5 中弃用的 `GetMotionControllerData` 和 `FXRMotionControllerData` 已被删除。
> 需要迁移到更新后的 API。
>
> _出处: [2025-07-22](https://github.com/pafuhana1213/UnrealEngine-UpdateTrackerReport/discussions/1)_

**移除单精度浮点服务器时间复制**

> 已移除使用 float 的服务器世界时间复制功能，今后仅支持 double。
>
> _出处: [2025-07-22](https://github.com/pafuhana1213/UnrealEngine-UpdateTrackerReport/discussions/1)_

**移除 `PlayerCameraManager` 中的旧函数**

> 在 5.0 中弃用的 `GetCameraCachePOV` / `GetLastFrameCameraCachePOV` 已被删除。
> 今后需要通过 `GetCameraCache()` 访问 `FCameraCacheEntry::POV`。
>

## 📌 重点关注模块

**Asset Registry / Cooker / Interchange**：冷收集 960→421 秒、Cooker 排序 5.3→0.6 秒、Interchange 场景导入 10 分钟以上→数十秒，这些从根本上改善大型项目迭代效率的优化在同月集中出现。直接作用于编辑器启动和 CI 的 Cook 时间。

**Material Translator (MIR) / Substrate**：新材质翻译器新增 21 个节点、支持 Custom HLSL、Volume / Array 纹理，与旧翻译器的功能一致性进一步接近；Substrate 的光照路径也与旧版 GBuffer 统一，渲染一致性得到增强。

**UAF / Animation**：从 SkeletonTemplateFramework 到 UAF (Unreal Animation Framework) 的正式迁移已经开始，从 Trait 堆栈的直接编辑、图表编译时验证，到 Anim Mixer 默认工作流改进，面向 AnimNext 世代的动画基础建设已全面展开。
