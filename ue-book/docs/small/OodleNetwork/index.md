## 用途

OodleNetwork 是 UE5 内置的**网络数据包压缩插件**，基于 RAD Game Tools 的 Oodle 压缩库，专门用于压缩网络游戏中的 UDP 数据包。

它的工作原理是：通过预先训练的**字典文件**（`.udic`），对网络数据包进行基于字典的压缩和解压缩。字典是从实际游戏网络流量中训练出来的，因此能针对特定游戏的网络协议特征实现高效压缩，显著减少网络带宽占用。

该插件作为 UE `PacketHandler` 系统的一个组件运行，在网络数据包发送前压缩、接收后解压缩，对上层游戏逻辑完全透明。

**为什么存在？** 多人在线游戏的网络带宽是关键资源，尤其在大量玩家同时在线时。OodleNetwork 利用数据包模式的相似性（同一个游戏的网络协议结构高度相似），通过字典训练来大幅压缩网络流量，降低带宽成本和延迟。

## 使用场景

- 你做了一个多人在线游戏（MMO、FPS、大逃杀等），需要减少服务器带宽消耗 → 用 OodleNetwork
- 你的游戏有大量并发网络连接，带宽成本高昂 → 用 OodleNetwork
- 你需要在不改变游戏逻辑的情况下优化网络传输 → 用 OodleNetwork（它是 PacketHandler 层的透明压缩）
- 你需要针对你的游戏协议定制压缩字典以获得最佳压缩比 → 用 OodleNetwork 的 Trainer Commandlet

## 蓝图用法

OodleNetwork 没有暴露任何 `BlueprintCallable` 或 `BlueprintReadWrite` 接口。它完全在网络底层（PacketHandler 层）透明运行，不直接面向蓝图。

配置通过 `DefaultEngine.ini` 的 `[OodleNetworkHandlerComponent]` 段完成，不通过蓝图节点。

## C++ 用法

### 头文件引入

```cpp
#include "OodleNetworkHandlerComponent.h"
#include "OodleNetworkArchives.h"          // 字典文件/抓包文件的归档格式
#include "OodleNetworkTrainerCommandlet.h"  // 字典训练命令行工具
#include "OodleNetworkAnalytics.h"          // 网络分析数据
```

### 配置（DefaultEngine.ini）

```ini
[OodleNetworkHandlerComponent]
; 是否启用 Oodle 压缩（默认 true）
bEnableOodle=true

; 服务端字典文件路径（相对于项目目录）
ServerDictionary=Content/Oodle/MyGameServer.udic

; 客户端字典文件路径（相对于项目目录）
ClientDictionary=Content/Oodle/MyGameClient.udic

; 何时在服务端启用压缩
; AlwaysEnabled = 始终启用（默认）
; WhenCompressedPacketReceived = 收到压缩包后才启用
ServerEnableMode=AlwaysEnabled

; 何时在客户端启用压缩
ClientEnableMode=AlwaysEnabled

; 以下仅在非 Shipping 构建可用：
; 如果项目目录有 .udic 文件就自动使用
bUseDictionaryIfPresent=false
; 抓包日志文件名前缀
PacketLogFile=PacketDump
```

### 控制台变量（Console Variables）

| CVar | 说明 |
|---|---|
| `net.OodleMinSizeForCompression` | 发送包最小压缩阈值（字节），低于此值的包不压缩，默认 0 |
| `net.OodleServerEnableMode` | 运行时覆盖服务端启用模式（优先于 ini 设置） |
| `net.OodleClientEnableMode` | 运行时覆盖客户端启用模式（优先于 ini 设置） |
| `net.OodleNetwork.TimeGuardThresholdMS` | 压缩/解压缩耗时告警阈值（毫秒），非 Shipping |
| `net.OodleNetwork.TimeGuardLimit` | 告警日志最大次数，默认 20，非 Shipping |

### 控制台命令（仅非 Shipping 构建）

| 命令 | 说明 |
|---|---|
| `Oodle ForceEnable On/Off/Default` | 强制启用/禁用 Oodle（调试用，不要在活跃连接上使用） |
| `Oodle Compression On/Off` | 启用/禁用发送方向的压缩（不影响接收方向的解压） |
| `Oodle Dictionary Load` | 重新加载字典文件 |
| `Oodle Dictionary Unload` | 卸载当前字典 |

### 字典训练工作流（C++ / 命令行）

OodleNetwork 的核心是**字典训练**，完整工作流如下：

**第一步：抓取网络数据包**

启动服务器时加上命令行参数：

```bash
# 启动服务器，开启抓包模式
MyGameServer.exe -OodleCapturing

# 可选：指定抓包百分比（0-100），用于采样
MyGameServer.exe -OodleCapturing -CapturePercentage=50
```

抓包文件（`.ucap`）保存在 `Saved/Oodle/Server/Input/` 和 `Saved/Oodle/Server/Output/` 目录下。

> **注意：** 每个目录应至少抓取 **100MB** 以上的数据才能生成有效的字典。

**第二步：合并抓包文件**

使用 Trainer Commandlet 合并多个抓包文件：

```bash
# 合并指定文件
UnrealEditor-Cmd.exe MyGame.uproject -run=OodleNetworkTrainer MergePackets Output.ucap File1.ucap,File2.ucap

# 合并目录下所有文件
UnrealEditor-Cmd.exe MyGame.uproject -run=OodleNetworkTrainer MergePackets Output.ucap All Directory/Path
```

**第三步：生成字典**

```bash
# 自动从 Saved/Oodle/Server 目录生成字典到 Content/Oodle
UnrealEditor-Cmd.exe MyGame.uproject -run=OodleNetworkTrainer AutoGenerateDictionaries

# 指定 changelist 过滤
UnrealEditor-Cmd.exe MyGame.uproject -run=OodleNetworkTrainer AutoGenerateDictionaries 12345

# 手动指定抓包文件生成字典
UnrealEditor-Cmd.exe MyGame.uproject -run=OodleNetworkTrainer GenerateDictionary OutputName all all File1.ucap,File2.ucap
```

生成的字典文件（`.udic`）存放在 `Content/Oodle/` 目录。

**第四步：配置并使用字典**

在 `DefaultEngine.ini` 中配置字典路径，然后正常启动游戏即可。

### 进阶用法

#### 字典训练参数调优

`UOodleNetworkTrainerCommandlet` 有以下可配置属性（通过 `DefaultEditor.ini` 设置）：

```ini
[/Script/OodleNetworkPlugin.OodleNetworkTrainerCommandlet]
; 是否在字典生成后进行压缩测试（会消耗部分数据包）
bCompressionTest=false
; 哈希表大小（默认 19，即 2^19 = 512K 条目）
HashTableSize=19
; 字典大小（默认 4MB）
DictionarySize=4194304
; 随机选择试验次数（默认 3）
DictionaryTrials=3
; 试验随机性百分比（默认 200）
TrialRandomness=200
; 试验代数（默认 1）
TrialGenerations=1
; 禁用随机试验
bNoTrials=false
```

#### 运行时重新加载字典

在开发/调试期间，可以不重启游戏就更换字典：

```
Oodle Compression Off
Oodle Dictionary Unload
; ... 运行 Trainer 生成新字典 ...
Oodle Dictionary Load
Oodle Compression On
```

> **警告：** 上述命令顺序很重要，错误顺序会导致 assert/crash。命令之间需要有几毫秒的间隔。

#### 启用 OODLE_DEV_SHIPPING

如果你是多人游戏 Mod 作者，可以在 Shipping 构建中保留字典训练功能：

```cpp
// 在包含 OodleNetworkArchives.h 之前定义
#define OODLE_DEV_SHIPPING 1
```

这会保留抓包、字典训练和自动字典查找功能，但会略微降低网络协议的反逆向工程保护。

## Demo 示例

### 最小化使用示例

OodleNetwork 是自动作为 PacketHandler 组件注入的，不需要手动编写 C++ 代码。以下是典型使用流程：

**1. Build.cs 依赖**

如果你需要在自己的模块中直接访问 OodleNetwork 的 API：

```csharp
PublicDependencyModuleNames.AddRange(new string[] {
    "OodleNetworkHandlerComponent",
    "PacketHandler"
});
```

**2. 检查压缩是否激活**

```cpp
#include "OodleNetworkHandlerComponent.h"

void UMyClass::CheckOodleStatus()
{
    // OodleNetworkHandlerComponent 作为 PacketHandler 的一部分自动创建
    // 通过 OodleComponentList 或 Handler 链访问（非 Shipping 构建）
    
    // 通常不需要直接操作——Oodle 会自动在 PacketHandler 链中工作
    UE_LOG(LogTemp, Log, TEXT("OodleNetwork is enabled by default and handles compression automatically."));
}
```

**3. 项目配置（DefaultEngine.ini）**

```ini
[OodleNetworkHandlerComponent]
bEnableOodle=true
ServerDictionary=Content/Oodle/MyGameServer.udic
ClientDictionary=Content/Oodle/MyGameClient.udic
```

## 模块依赖

从 `OodleNetworkHandlerComponent.Build.cs` 的 `PublicDependencyModuleNames` 提取：

| 模块 | 用途 |
|---|---|
| `PacketHandler` | UE 网络数据包处理器框架，Oodle 作为其组件运行 |
| `Core` | UE 核心库 |
| `CoreUObject` | UObject 系统 |
| `NetCore` | 网络核心库，提供分析和连接管理 |
| `Engine` | 引擎核心模块 |
| `Analytics` | 分析系统，用于上报压缩统计信息 |

此外，OodleNetwork 依赖 Oodle SDK 的原生库（位于 `Sdks/` 目录），支持以下平台：Win64、WinArm64、Mac、Linux、LinuxArm64、Android（arm64-v8a/armeabi-v7a/x86/x86_64）、iOS、tvOS。

运行时依赖：`Content/Oodle/*.udic` 字典文件会自动打包到最终构建中。
